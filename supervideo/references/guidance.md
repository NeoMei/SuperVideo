# 对话引导

把“帮我做个视频”逐步变成双方理解一致的结果。采用 Superpowers 的渐进澄清、方案比较与先确认后制作思路；本指南自包含，无需调用或安装 Superpowers。用户直接在对话里选择和修改，不另建任务清单网站。

## 从当前阶段进入

- 新作品、目标模糊：先读可用资料和既有对话，复述已知信息，再问最影响讲法的一项。等待回答时可做资料检查，不替用户决定尚未明确的目标。仅在需要用引擎导入来源或保存计划时 `start`；能先从附件和对话澄清时不必提前建工程。
- 新作品、要求已完整：直接展示制作简报及推荐讲法，请用户确认；不要把已给的信息改写成一串问题。
- 当前简报已获确认：进入讲稿/分镜，随后样片与成片；不要重复要求确认同一方向。
- 现有作品局部修改：先 `status`，只处理本次改动及其影响。例如“只加音乐”走 `music`，保留原旁白与画面，不重问受众和风格。
- 续做或交接：先读现有简报、对话和 `status`，说明已完成部分与下一步。记录缺失时只补关键缺口，不把文件存在当作已确认。

## 怎样问

每轮一个决策问题，按“观众与使用场合 → 观看后结果与内容范围 → 表现方式”找最重要的缺口；已有答案直接跳过。问题给 2–3 个简短、互斥的例子或选项，适用时标明推荐项及一句理由，也允许自由回答。不要在一句话里夹带受众、场合、时长等多个必答项。

当目标足够明确而讲法有实际分歧时，先比较 2–3 种成片思路并推荐一种，例如“逐页完整讲解：覆盖全面、较长；重点串讲：突出结论、压缩细节”。当只有一种路线符合需求时，直接给推荐方案。可推荐顺序、节奏与呈现方式；不能把缩减用户所需内容当作默认精简。

按产出补充关键问题，不按文件扩展名套问卷：

| 产出 | 优先明确的结果 | 必须落到方案中的内容 |
| --- | --- | --- |
| PPT 解说 | 谁看、希望理解哪些结论、覆盖哪些页 | 原页自动配音与字幕、讲解深度、重点页；不默认录人像或现场授课 |
| 绘本 | 年龄段、故事体验或阅读目标 | 忠于情节、旁白/角色对白、插图与角色一致性 |
| 网页教程 | 观众要独立完成哪项任务 | 起点、操作范围、可见成功结果与动作提示；录制仅执行已授权步骤 |
| 教学动画 | 学习者基础、看完能解释或完成什么 | 知识范围、关键变化关系、演示/实验及检验理解的例子 |

音色、横竖屏、字幕、音乐和时长等已有偏好沿用；其余给出可修改建议，一并放入简报。新工程可建议百炼默认音色、横屏与半透字幕；PPT/绘本保持完整全屏页面。BGM 有明确来源则提议用途与配音避让；没有来源可提议暂不加，用户要求找音乐时再按授权寻找。时长先给估算，成片以实际音频测量为准；无法同时满足内容覆盖与时长时说明取舍，让用户决定。

仅要求“加这段音乐，讲话时小声一点”时，可先声明全片铺底、低音量（如 0.1）、按片长循环/裁切、短淡入淡出和 ducking，再在本次修改授权内试做，无需逐项问参数。记录为本次执行建议，不伪称用户指定；用户已指定片段或参数则遵从其选择。修改后再 `status` 检查阶段状态：只有当前 script/sample 确认有效才制作完整预览。若已失效，核对旧内容确认与本次原话的覆盖范围，按真实 evidence 更新相应记录；不够覆盖的只问缺口，不能因“只是音乐”而自动编造 waiver。

## 确认制作简报

方向足够明确后，用约 5–8 行呈现具体成片承诺，供用户改动或确认：

- 给谁看、用于什么场合；看完能理解或完成什么。
- 使用哪些资料、覆盖哪些内容；需要补充或核实的内容。
- 推荐的模式、叙事顺序、讲解深度和关键画面/动作。
- 大致时长、画幅；配音语言/音色与字幕表现。
- BGM 来源或暂不加入、使用范围和讲话时降低音乐的安排。
- 如何判断达到目标，以及代表样片应覆盖哪些难点。
- 尚待决定的关键项，以及下一步展示什么。

区分“用户已指定”和“本次建议”，不要把建议写成既定选择。结尾只确认当前方向，例如“按这个方案展开讲稿和分镜，可以吗？”用户明确表示“按推荐做”即可推进；沉默、超时或回复另一件事不能当作确认。

一个简短例子：用户已说明是给新员工看的产品 PPT，目标是五分钟内能讲清三个卖点。可回复：“建议保留原页做重点串讲，围绕三个卖点组织，关键图表加高亮。预计约五分钟，中文百炼旁白，横屏全屏加半透字幕；音乐暂不加。样片选一页产品图和一页图表，检查能否说清卖点、字幕是否遮挡内容。按这个方向展开讲稿，可以吗？”仅在这些要求已知或明确标成建议时使用，不把例子当作所有作品的默认设定。

## 从确认到成片

1. **方向确认 → 讲稿/分镜。** 将简报落成具体场景，展示讲稿与画面安排。只有用户对当前内容的确认，或覆盖该阶段的明确委托，才能记录相应 `script` approval/waiver。
2. **讲稿确认 → 代表样片。** 一般选约 15–30 秒或足够覆盖关键变化的片段，实际长度服从语音和场景边界。让用户判断声音、节奏、字幕、画面与音乐；网页样片要包含动作前提示、点击和结果，教学样片要有关键关系变化。
3. **样片确认 → 完整视频。** 沿用已确认表现制作，展示真实 MP4；按简报中的结果标准检查，而不只报告文件已生成。
4. **修改与交付。** 修改集中到受影响部分，确认失效时只重新审阅受影响内容。最终 `deliver` 仍绑定精确完整成片；技术通过不替代用户对内容和观感的判断。

用户明确要求合并确认或全权委托时，保留其原话与实际覆盖阶段，沿用授权继续，不重复拦住同一事项。先形成实际讲稿/分镜，再按当前 revision/scope 记录 script waiver；先生成并检查真实样片，再记录 sample waiver 并制作全片。方向简报不代替阶段产物，所有 waiver 仍须有对应阶段的真实授权。宽泛的“方向可以”只确认已展示方向；不扩大为对未展示讲稿、未执行网站动作或最终成片的授权。

## 记录与恢复

工程建立后由宿主维护工程目录内的 `制作简报.md`，保留：当前阶段、目标与范围、已选表现方案、待确认项、用户确认原话或对话定位及对应版本、后续变更和当前预览位置。建立工程前可先在对话中保留；不要为一张简报新增服务或数据库。

简报是宿主的制作记录，不向 `project.json` 塞入未知字段，不发明 `brief` action 或 approval stage。真正 `script/sample/final` 状态以现有引擎和对应 evidence 为准；两者冲突时先核对最近的实际修改与用户原话，不自动补造确认。用户只改局部就记录该项变更，改变受众或目标才重开相关简报内容。需要交接引导记录时单独附上简报；当前 `deliver` 不自动包含它。
